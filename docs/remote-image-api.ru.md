# Подключение удалённого API для генерации изображений

Это руководство описывает подключение Wombo к image API на другой машине, например к InterHost. Backend Wombo обращается к удалённому серверу напрямую; браузер обращается только к Wombo.

## Что потребуется

- Установленный и работающий Wombo.
- Машина с InterHost или другим image API, совместимым с OpenAI Images API.
- Сетевая доступность удалённой машины с компьютера, где запущен backend Wombo.
- Доступный порт image API, например `9001`.
- Точный ID модели, который сервер принимает в поле `model`.

## 1. Проверьте API на удалённой машине

Убедитесь, что сервис слушает сетевой интерфейс удалённой машины, а не только `127.0.0.1`. Для примера далее используется адрес `192.168.1.50` и базовый URL `http://192.168.1.50:9001/v1`.

API должен поддерживать оба маршрута:

- `POST /images/generations` — создание изображения по текстовому запросу.
- `POST /images/edits` — создание/редактирование изображения с загруженным PNG или JPEG референсом через `multipart/form-data`.

Сервер генерации должен принимать `model`, `prompt`, `n`, `size` и `response_format=b64_json`, а возвращать изображение в OpenAI-совместимом формате:

```json
{
  "data": [
    { "b64_json": "..." }
  ]
}
```

Маршрут edits необходим: Wombo генерирует боковой вид персонажа, затем передаёт его как референс для фронтального и заднего видов. Если API умеет только генерацию по тексту, весь трёхракурсный сценарий работать не будет.

Если API требует ключ, проверьте, что он принимает стандартный заголовок:

```http
Authorization: Bearer <ключ>
```

## 2. Проверьте сетевую доступность

На машине с backend Wombo выполните в PowerShell:

```powershell
Test-NetConnection 192.168.1.50 -Port 9001
```

Замените адрес и порт на значения удалённой машины. У `Test-NetConnection` должно быть `TcpTestSucceeded : True`. Если команда не проходит, проверьте сетевую маршрутизацию, firewall удалённой машины и то, что сервис слушает нужный интерфейс и порт.

Проверьте HTTP API. Укажите реальный model ID и при необходимости добавьте авторизацию:

```powershell
$headers = @{ Authorization = "Bearer YOUR_API_KEY" }
$body = @{
  model = "interhost/your-model-id"
  prompt = "A small red game character on a plain green background"
  n = 1
  size = "1024x1024"
  response_format = "b64_json"
} | ConvertTo-Json

Invoke-RestMethod `
  -Uri "http://192.168.1.50:9001/v1/images/generations" `
  -Method Post `
  -Headers $headers `
  -ContentType "application/json" `
  -Body $body
```

Если авторизация не нужна, удалите параметры `-Headers $headers` и переменную `$headers`. Успешный ответ должен содержать `data[0].b64_json`.

## 3. Настройте Wombo

Добавьте или измените следующие строки в существующем `.env` в корне проекта:

```dotenv
IMAGE_API_BASE_URL=http://192.168.1.50:9001/v1
IMAGE_API_KEY=YOUR_API_KEY
IMAGE_MODEL=interhost/your-model-id
```

Замените адрес и ID модели на свои. Если удалённый API не требует ключ, оставьте `IMAGE_API_KEY` пустым:

```dotenv
IMAGE_API_KEY=
```

Указывайте базовый URL до `/v1`, без `/images/generations` и `/images/edits`: Wombo самостоятельно добавляет конечный маршрут. Можно использовать `http://` в доверенной сети или `https://` с корректной настройкой TLS.

После изменения `.env` перезапустите приложение:

```powershell
npm run dev
```

Откройте `http://localhost:5173`, создайте или откройте персонажа и выберите настроенную модель в списке image models. Она появится под именем `Custom API: <model ID>`. Если это первая генерация персонажа, Wombo выполнит три последовательных запроса: side, front и back.

## 4. Частые проблемы

- **Connection refused / timeout:** InterHost не слушает сетевой интерфейс удалённой машины, порт закрыт firewall или backend Wombo не имеет сетевого доступа к этому адресу.
- **404 на генерации или edits:** неверный базовый URL либо сервис не предоставляет один из требуемых маршрутов. Убедитесь, что `/v1` присутствует только в `IMAGE_API_BASE_URL`, а Wombo добавляет `/images/generations` или `/images/edits`.
- **401 / 403:** проверьте `IMAGE_API_KEY` и поддержку `Authorization: Bearer ...`. При отсутствии авторизации переменная должна быть пустой.
- **Модель не найдена:** задайте в `IMAGE_MODEL` точный ID, который принимает удалённый сервер.
- **Ответ не содержит изображение:** API должен возвращать base64 в `data[0].b64_json`. Другие форматы ответа Wombo сейчас не принимает.
- **Ошибка при создании front/back видов:** проверьте multipart маршрут `/images/edits`, поддержку PNG/JPEG и передачу `model` и `prompt` вместе с полем `image`.
- **Новая модель не видна:** перезапустите backend после изменения `.env` и обновите страницу.

## Безопасность

`IMAGE_API_BASE_URL` и `IMAGE_API_KEY` используются только backend-сервером. Не помещайте ключ в код браузера и не публикуйте `.env`. Ограничьте доступ к порту API доверенной сетью; не открывайте его в публичный интернет без дополнительной аутентификации и сетевых ограничений.

Удалённый API получает prompts и референсные изображения персонажей. Учитывайте правила хранения и обработки данных на машине и в сервисе InterHost.
